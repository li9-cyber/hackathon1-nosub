# 共用匹配算法

`service.match(state, job)` 是卡片、重新匹配與深度分析的唯一計分入口。
CV 和 JD 都呼叫 `normalize()`，底層使用既有 Skill Registry / `normalize_concept`。

`compatibility.py` 讀取舊專案的 `alternatives` 要求，不改寫已保存原文。
舊 AND 組合取最低證據程度，OR 分支取最佳組合；原句重新建立精確位置。
專案開啟時只重算失效的匹配並保存，無需重新呼叫 Techmap 或 DeepSeek。

`fcdt/` 和 `data/` 保留交接包的純計算碼與市場資料。正式公式呼叫原有 `score_a`：u=1+W，Direct=1、Partial=0.5、Unverified=0，Required/Preferred=80/20。
市場 JSON SHA-256：bb04bedaddfbc557cee94b4c2774f4cbc6f0cdc1b2122a40162fd5d54df4d7d1。

依本次需求，產品整合簡化原引擎的出分限制：

- 每個要求搜尋目前保存的證據；未找到仍按 0 計算，不判定使用者不懂。
- 明確使用經歷為直接證據；只有技能欄、自述程度或已登記相關技能為部分證據。
- 未知名稱保留；未知職類不借用其他職類權重，W=0。
- 資格條件另外展示，未確認不等於確定不符合；技能分數不因資格不足封頂。
- 只有資格要求時以相同公式顯示要求證據覆蓋；沒有任何要求才無法計分。
- OR 為一個單位，取最大 W 和最佳證據；相同標準技能／程度去重，Required 優先。
- `policy.py` 管理 80／40 顯示閾值及有限的相關技能映射；分數不是錄取機率。

JD 20 秒、深度分析 40 秒是目標。超過時前端提示需要更多時間，同一次請求繼續；最終網路上限 55／70 秒，不自動重試。
